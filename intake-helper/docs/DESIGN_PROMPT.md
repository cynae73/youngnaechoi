# 디자인 프롬프트 — 접수 도우미 (테스트 버전)

아래 프롬프트를 화면 설계의 기준으로 삼아 적용했다. 이후 화면을 고치거나 새 화면을 추가할 때도 이 프롬프트를 그대로 다시 사용한다.

---

## 역할
당신은 클라이언트마다 서로 다른 시각 정체성을 만들어 주기로 알려진 디자인 스튜디오의 디자인 리드다. 이 클라이언트는 이미 흔하고 틀에 박힌 시안을 거절했다. 이 프로젝트에만 해당하는 분명한 관점으로 색, 글꼴, 배치를 결정하라.

## 대상과 목적
- 제품: 시험·검사기관 접수 담당자가 시험검사의뢰서(사진·PDF·엑셀)를 읽어 연구관리시스템 민원접수 등록 값으로 바꾸고, 사람이 대조·확정한 뒤 접수하는 업무용 도구.
- 사용자: 하루에 여러 건을 반복 처리하는 연구원·접수 담당자. 한국어 사용자, 윈도우 PC, 오프라인에 가까운 사내망.
- 핵심 업무: **원본과 읽은 값을 대조하고, 불확실한 값만 빠르게 확정한다.** 틀린 접수는 청구·성적서 오류로 이어지므로 정확성이 속도보다 먼저다.
- 화면의 어조: 실험실 장비 화면처럼 조용하고 정밀하다. 홍보 문구, 장식, 감탄이 없다.

## 시각 방향: "검수대"
접수 담당자의 책상은 원본 서류 옆에서 한 칸씩 대조하는 검수대다. 화면은 그 책상을 닮는다.
- 서류(원본)와 입력값이 **항상 나란히** 보인다. 이것이 이 화면의 가장 눈에 띄는 요소다.
- 기관의 기존 시스템(KAFRI)과 엑셀에서 이미 쓰는 **노란색 = 확인 필요**의 의미를 그대로 이어받는다. 새 의미를 만들지 않는다.
- 나머지는 모두 조용하다. 대담함은 한 곳(원본·입력값 대조 영역과 접수 현황 띠)에만 쓴다.

## 색 (이름: 값)
- 유리판 `#EAEEF1`: 작업면 배경. 차가운 회색 유리.
- 종이 `#FFFFFF`: 서류·입력 영역.
- 잉크 `#17212B`: 본문. 순수 검정이 아니라 푸른 잉크.
- 시약 청색 `#2349C8`: 주요 행동과 선택 상태 하나에만 쓴다.
- 형광펜 `#FFE45C`(배경)/`#7A5B00`(글자): 확인 필요. 기존 시스템의 노란 칸과 같은 의미.
- 적정 녹색 `#1F7A4D`: 확정·성공. 적색 `#C2362B`: 오류·중단.
- 다크 모드는 같은 이름의 값을 어둡게 재정의한다(유리판 `#12181E`, 종이 `#1A222A`, 잉크 `#E6ECF1`).
- 그라데이션, 장식용 그림자, 색 번짐을 쓰지 않는다. 상태는 색만으로 구분하지 않고 글자와 모양을 함께 쓴다.

## 글꼴
- 한 가지 글꼴: Pretendard Variable(내장). 대체: Noto Sans KR, 맑은 고딕.
- 역할은 굵기와 크기로 나눈다: 제목 20/28 600, 본문 14/22 400, 표 13/20 400, 보조 12/18 400.
- 숫자는 모두 `tabular-nums`로 열을 맞춘다(사업자번호, 날짜, 금액, 건수). 코드 값은 고정폭 글꼴 대신 같은 글꼴의 숫자 정렬로 처리한다.
- 대문자 라벨, 제목 위 소제목, 가운뎃점으로 이은 메타 문자열, 화살표 붙은 버튼 글을 쓰지 않는다.

## 배치
```
┌ 상단줄: 제품명 · 서버 연결 상태 · [드라이런: 서버에 저장하지 않음]
├ 좌측 레일(순서가 있는 3단계: 불러오기 → 검토 → 등록)
│ ┌ 접수 현황 띠: 건마다 한 칸, 상태색(확정/확인필요/오류/미검토)
│ ├ 건 목록(밀도 높은 표, 카드 아님) │ 상세: [원본 뷰어] | [입력값 폼]
│ └ 폼은 묶음별(의뢰업체 / 계산서·성적서 / 시료 / 시험항목 / 통보), 불확실 칸은 형광펜
└ 등록 단계: 전송될 값 미리보기 → 확인 → 결과 표
```
- 왼쪽 정렬을 기본으로 한다. 표는 열 머리글과 숫자 정렬을 지킨다.
- 번호 표시는 정말 순서가 있는 3단계 레일에만 쓴다.
- 모서리는 4px 하나로 통일한다. 카드 격자, 같은 그림자 반복을 쓰지 않는다. 구분은 선과 여백으로 한다.
- 화면 너비 1100px 미만에서는 목록과 상세를 위아래로 쌓는다. 가로 스크롤 없이 모바일 폭(360px)에서도 읽혀야 한다.

## 움직임
- 사용자가 하지 않은 움직임은 쓰지 않는다. 진행 중 작업의 상태 표시(막대 하나)만 예외다.
- 사용자의 행동에 답하는 움직임만 허용한다: 패널 열림, 칸 확정 시 형광펜이 사라지는 전환(150ms).
- `prefers-reduced-motion`이면 전환을 끈다.

## 문구 원칙
- 사용자가 이해하는 말로, 문장형 한글, 능동형. 버튼은 실제 일어나는 일을 쓴다: "엑셀로 저장", "과거 접수에서 업체 정보 가져오기", "이 건 확정".
- 같은 동작은 화면 어디서나 같은 이름. 버튼 "확정" → 알림 "확정했습니다".
- 오류와 빈 화면은 무엇이 문제이고 무엇을 하면 되는지 말한다. 사과하지 않는다.
- 드라이런임을 항상 보여 준다. 서버에 저장되지 않는다는 사실이 화면에서 한 번도 사라지지 않는다.

## 품질 하한
키보드 포커스 표시, 4.5:1 이상의 글자 대비, 클릭 영역 32px 이상, 이미지에 대체 텍스트, 오류 영역에 `role="alert"`, 진행 표시에 `aria-live`.

## 시안 점검 질문
1. 서류와 입력값이 한 화면에서 나란히 보이는가?
2. 노란색이 "확인 필요" 외의 뜻으로 쓰이지 않았는가?
3. 장식이 하나라도 업무 정보를 전달하지 않고 있는가? 있으면 뺀다.
4. 위 "기본값 같은 디자인" 목록(크림색 바탕+세리프, 검정 바탕+형광색, 신문식 칸, 같은 카드 반복, 대문자 라벨)과 닮았는가? 닮았으면 다시 한다.
