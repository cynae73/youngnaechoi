# 접수 도우미 서버 배포 안내 (관리자용)

여러 담당자가 한 서버의 주소로 접속해서 쓰는 방식입니다. 담당자는 아무것도 설치하지 않고 브라우저만 쓰면 됩니다.

## 1. 구성과 동작

```
담당자 PC (브라우저)  ──HTTPS──▶  접수 도우미 서버  ──사내망──▶  연구관리시스템(KAFRI)
                                   · 접속 비밀번호 + (선택) IP·사번 제한
                                   · 사용자별 세션(사번 연결이 서로 섞이지 않음)
                                   · 접속 기록(사번·시각·IP·동작)
```

- 서버는 의뢰서 파일, 업체 정보, 접수 내용을 **저장하지 않습니다**(메모리에서 처리 후 버림). 불러온 내용은 담당자 브라우저에만 있습니다.
- 접속 기록(`logs/audit-YYYY-MM.log`)에는 사번, 시각, IP, 동작(접속·연결·변환 건수 등)만 남고 의뢰서 내용, 업체명, 파일 이름, 비밀번호는 남지 않습니다.
- 사번 로그인 상태는 서버 메모리의 사용자별 세션에 있습니다. 서버를 재시작하거나 `SESSION_HOURS`(기본 8시간) 동안 쓰지 않으면 다시 연결해야 합니다.
- **내 PC 전용 모드는 그대로입니다.** `.env` 에 `HOST` 를 쓰지 않으면 예전처럼 127.0.0.1 에서만 열리고 접속 비밀번호가 없습니다(`시작.bat`).

## 2. 준비물
- 서버 1대(Linux 또는 Windows). **연구관리시스템에 접속할 수 있는 사내망**에 있어야 합니다.
- Node.js 18 이상.
- 담당자가 접속할 주소(예: `https://intake.기관도메인`)와 HTTPS 인증서(권장. 아래 4장).
- 정하기: 접속을 허용할 PC의 IP 대역, 사용할 담당자 사번 목록.

## 3. 설치

### Linux (systemd)
```bash
git clone <저장소> /opt/intake-helper && cd /opt/intake-helper
git checkout claude/keen-hamilton-62m9qs      # 사용할 브랜치/태그
sudo bash deploy/install.sh --url https://intake.example.go.kr \
     --ips 10.20.0.0/24 --employees 100123,100456
```
- Node 확인 → `npm ci` → `.env` 생성(**접속 비밀번호 자동 생성, 화면에 한 번 출력**) → systemd 서비스(`intake-helper`) 등록·시작 → 점검까지 한 번에 합니다.
- 서비스 전용 계정(`intake`)으로 최소 권한(`NoNewPrivileges`, `ProtectSystem=strict`)으로 실행합니다. `/home` 아래보다 `/opt` 에 두세요.
- 갱신: `git pull && sudo bash deploy/install.sh` (`.env` 는 유지됩니다).

### Windows (관리자 PowerShell)
```powershell
cd C:\intake-helper
powershell -ExecutionPolicy Bypass -File deploy\install.ps1 -Url https://intake.example.go.kr `
    -Ips 10.20.0.0/24 -Employees 100123,100456
```
- `.env` 생성(접속 비밀번호 자동 생성) → 방화벽 허용 → 부팅 때 자동 시작되는 예약 작업(`IntakeHelper`, SYSTEM 계정) 등록·시작 → 점검까지 합니다. 로그는 `logs\server.log`.
- 중지/시작: `Stop-ScheduledTask -TaskName IntakeHelper` / `Start-ScheduledTask -TaskName IntakeHelper`

### 점검
`npm run check` (또는 `node deploy/check.js --url http://127.0.0.1:8791`): Node 버전, 라이브러리, 설정, 기록 폴더, 양식 규칙, 연구관리시스템 연결 가능 여부, 서버 응답을 확인합니다.

## 4. HTTPS (사번과 의뢰서가 오가므로 권장)
- **방법 1: 이 프로그램이 직접 HTTPS** — `.env` 에 `TLS_CERT=certs/server.crt`, `TLS_KEY=certs/server.key` (기관 인증서 파일을 `certs/` 에 둠). 인증서 교체 후 서비스 재시작.
- **방법 2: nginx/IIS 등 프록시 뒤** — `.env` 에 `HOST=127.0.0.1`, `TRUST_PROXY=1`, `PUBLIC_URL=https://…`. `deploy/nginx.conf.example` 참고. 프록시는 접속자 IP 를 `X-Forwarded-For` 로 **덮어써서** 넘겨야 합니다(IP 제한·접속 기록이 이 값을 씁니다).
- HTTPS 로 열면 쿠키에 `Secure` 와 HSTS 가 자동으로 붙습니다. HTTP 로 열면 시작할 때 "주의"가 표시됩니다.

## 5. 설정(.env) 요약 — 전체는 `.env.server.example`

| 항목 | 설명 |
|---|---|
| `HOST` / `PORT` | 열 주소와 포트. `0.0.0.0` 이면 다른 PC 접속 가능 |
| `PUBLIC_URL` | 사용자가 입력하는 주소. 이 주소(Host)가 아닌 요청은 거부 |
| `ACCESS_PASSWORD` | **접속 비밀번호(8자 이상, 공유 서버에서는 필수).** 없으면 서버가 시작하지 않음. 5번 틀리면 그 IP 10분 차단 |
| `ALLOWED_IPS` | 접속 허용 IP/대역(CIDR, IPv4). 비우면 제한 없음 |
| `ALLOWED_EMPLOYEES` | 연결 허용 사번. 비우면 어떤 사번이든 가능 |
| `TLS_CERT` / `TLS_KEY` | 직접 HTTPS |
| `TRUST_PROXY` / `SHARED` | 프록시 뒤 / 127.0.0.1 에 묶여 있어도 공유 서버로 취급(비밀번호 필수) |
| `SESSION_HOURS`, `MAX_UPLOAD_MB`, `LOG_DIR` | 유휴 만료, 업로드 상한, 기록 폴더 |
| `ANTHROPIC_API_KEY` | (선택) 서버가 사진·스캔을 직접 AI로 읽음. **이 서버를 쓰는 모두의 사용량이 이 키로 청구됨** |

## 6. 담당자에게 알려 줄 것
1. 접속 주소 + **접속 비밀번호**(`.env` 의 `ACCESS_PASSWORD`).
2. 사용 안내서: `<접속 주소>/guide.html` 을 열어 A4 1장으로 인쇄(주소가 자동으로 채워짐). 비밀번호와 관리자 연락처는 손으로 적어 배포. 빈칸 PDF: `docs/담당자_사용안내서.pdf`.
3. 사번은 본인 것만 쓰기, 비밀번호 공유 금지.

## 7. 운영
- 기록: `logs/audit-*.log`(JSON 한 줄씩). 동작: `access_ok/fail`, `login`, `login_denied`, `convert`, `excel_export`, `signout`, `ip_denied` 등. 보관 기간은 기관 정책에 맞춰 정리하세요(자동 삭제 없음).
- 로그 확인: `journalctl -u intake-helper -f` (Linux) / `logs\server.log` (Windows).
- 비밀번호 변경: `.env` 의 `ACCESS_PASSWORD` 수정 후 서비스 재시작(모든 담당자 재접속).
- 상태 확인(모니터링): `GET /healthz` → `{"ok":true}` (인증 없음, 정보 없음).

## 8. 보안 모델과 한계 — 도입 전에 읽어 주세요
- **연구관리시스템 로그인은 사번만 보내고 비밀번호가 없습니다.** 이 서버가 접속 비밀번호를 아는 사람에게 "아무 사번"으로 연결해 주는 구조가 되지 않도록 `ALLOWED_EMPLOYEES` 와 `ALLOWED_IPS` 를 반드시 쓰세요. 접수자 기록의 신뢰는 이 두 가지와 접속 기록에 달려 있습니다. 담당자가 다른 사람 사번으로 연결하는 것은 기술적으로 막을 수 없습니다(개인별 비밀번호 체계가 필요하면 별도 개발).
- 연구관리시스템 입장에서는 여러 담당자의 요청이 **서버 한 대의 IP** 에서 오게 됩니다. 기존 접속 코드는 요청에 고정 IP 값(127.0.0.100)을 보냅니다. 도입 전에 연구관리시스템 담당자와 이 사용 방식을 협의하세요.
- 현재 서버 저장 기능이 없어 **연구관리시스템에 쓰는 요청은 하지 않습니다**(조회만). 저장 기능을 붙일 때는 접수자 책임 소재를 다시 정해야 합니다.
- 의뢰서 사진을 Claude 앱 또는 API로 처리하면 업체명·연락처·사업자번호가 외부 서비스로 전송됩니다. docx·hwpx·글자 PDF 규칙 변환은 서버 밖으로 나가지 않습니다. 기관 정보보안·개인정보 정책에 맞는 방식만 안내하세요.
- 한 프로세스(Node.js 1개)로 동작합니다. 수십 명 규모를 가정하며, 세션은 메모리에 있어 재시작하면 사라집니다.

## 9. 문제 해결
| 증상 | 확인 |
|---|---|
| 서버가 시작하지 않음 | 화면/로그의 "설정 오류" 문구(접속 비밀번호 없음, `PUBLIC_URL` 형식, 인증서 경로 등) |
| "허용되지 않은 요청입니다" | 브라우저 주소가 `PUBLIC_URL`/`ALLOWED_HOSTS` 와 다름(IP로 접속했는데 도메인만 등록 등). 프록시가 `Host` 를 바꾸는지 확인 |
| "이 주소에서는 접속할 수 없습니다" | `ALLOWED_IPS`. 프록시 뒤라면 `TRUST_PROXY=1` 과 `X-Forwarded-For` 덮어쓰기 확인 |
| 비밀번호 입력창이 계속 뜸 | 쿠키 차단, HTTP/HTTPS 혼용(Secure 쿠키), 서버 재시작 직후 |
| 사번 연결이 안 됨 | `ALLOWED_EMPLOYEES`, 서버에서 연구관리시스템에 접속 가능한지(`npm run check`) |
| 큰 PDF 변환이 끊김 | 프록시의 `client_max_body_size`/`proxy_read_timeout`, `MAX_UPLOAD_MB` |
